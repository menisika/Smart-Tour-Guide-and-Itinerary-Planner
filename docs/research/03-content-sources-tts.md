## 1. Резюме

1. **[Замер] Беларусь — «средне-бедный» регион по открытым данным о достопримечательностях, но не пустой.** В радиусе 1,5 км от центра в Wikidata: Минск — 873 объекта с координатами (статья в en-Wikipedia есть у 86, в ru — у 285, в be — у 510); Прага — 5227 (en — 313); Краков — 2609 (en — 258). В Бресте и Витебске статьи в en-Wikipedia есть у 7 объектов из ~400. **Основной язык знаний о беларуских местах — белорусский, а не английский и не русский.**
2. **[Замер] Wikidata хорошо закрывает белорусский реестр наследия:** 8160 элементов со свойством P632 (номер в Государственном списке), из них 6475 с координатами, 3331 с фото; статьи есть в be-Wikipedia у 1753, в ru — у 702, в en — у 106. Это лучший машиночитаемый «скелет» для Беларуси.
3. **[Замер] OSM в Беларуси пригоден для геометрии и категорий, слаб для связей и часов работы в малых городах:** в Минске у 64% музеев (48 из 75) заполнены часы работы, в Несвиже — у 1 из 6; у достопримечательностей Минска ссылку на Wikidata имеют лишь ~4%.
4. **[Ф] Ни OpenAI, ни Anthropic, ни Google Gemini API, ни ElevenLabs официально не обслуживают Беларусь и Россию** (пользователей и разработчиков). Для запуска с беларуским юрлицом/из Беларуси «мировой» стек напрямую недоступен — это главная развилка ADR.
5. **[Ф] Региональные альтернативы есть, но с оговорками:** YandexGPT/SpeechKit (оферта Yandex Cloud описывает только резидентов и нерезидентов РФ и Казахстана, отдельного пути для Беларуси не нашёл); SaluteSpeech **закрыл подключение новых клиентов с 15.07.2026**; GigaChat для новых клиентов переведён на cloud.ru с 01.09.2026.
6. **[Ф] Белорусский TTS в 2026 году существует:** Gemini 3.8 Flash TTS (130+ языков, включая белорусский), OpenAI gpt-4o-mini-tts (белорусский в списке, но голоса «оптимизированы под английский», модель закрывается 06.01.2027), ElevenLabs (заявлен, но недоступен в BY/RU), Silero (белорусская модель под MIT, но **без автоматической расстановки ударений**). У Azure голоса be-BY не нашёл; у Yandex SpeechKit белорусского нет в документации.
7. **[Ф] Цена TTS упала до копеек:** Gemini 3.8 Flash-Lite TTS — $6 за 1 млн аудио-токенов (25 токенов/с → ≈$0,009 за минуту) до 31.12.2026, затем $12; ElevenLabs — $0,04–0,08 за 1 тыс. символов; Yandex SpeechKit API v1 — 1342 ₽ за 1 млн символов (с НДС).
8. **[В] Себестоимость подготовки одного места (3 варианта × 2 языка, 2 мин аудио на рассказ) — от ≈$0,13 (дёшево) через ≈$0,27 (средне) до ≈$1,5 (премиум).** Город на 100 мест — $13–150. Это перестало быть ограничением; дорогими остаются ручная проверка и «живые» функции.
9. **[Ф] Галлюцинации при пересказе источника не исчезли:** на лидерборде Vectara (22.10.2026) лучшие модели ошибаются в 1,8–5% саммари, флагманы GPT-5.5/Claude/Gemini 3 Pro — в 9–14%. Значит, «≥95% утверждений привязаны к источнику» **реалистично только с отдельным этапом проверки на уровне утверждений**, а не «по построению».
10. **[В] Метрику «≥95%» нужно переопределить:** считать отдельно (а) долю утверждений с цитатой (citation coverage), (б) долю цитат, которые действительно подтверждают утверждение (citation precision, по выборочной человеческой разметке), (в) долю ошибок, найденных людьми. Цели: ≥98% покрытия после фильтра, ≥95% точности по выборке, порог фиксировать по нижней границе доверительного интервала.
11. **[Ф] Отраслевой ориентир длины рассказа — около 2 минут (250–300 слов), одна-две мысли на остановку** (Bloomberg Connects, Guide-ID). Smartify: персонализированные туры дослушивают до конца чаще (65% против 52%), на родном языке слушают дольше (≈17 мин против <11).
12. **[В] Нужен не один рассказ, а набор форматов:** вступление к маршруту, «у места» (60–150 с), «в пути» (связки 20–60 с), «подробнее» по запросу, финал; сквозная тема маршрута.
13. **[Ф] Конкуренты уже делают то, чего не было в концепте:** Google Maps с конца января 2026 года даёт Gemini в пешей навигации (вопросы голосом о месте, достопримечательности по пути); множество AI-гидов 2026 года умеют распознавать здание по камере и отвечать на голосовые вопросы. **[В] Голосовой вопрос «что это?» и «расскажи подробнее» стали обязательными ожиданиями.**
14. **[Ф] Realtime-диалог стоит центы за минуту:** Gemini 3.8 Live — $0,005 за минуту входного аудио и $0,018 за минуту выходного; OpenAI gpt-realtime-mini — $10/$20 за 1 млн аудио-токенов. **[В] Диалог на прогулку — ≈$0,25–0,8, распознавание по камере — ≈$0,03–0,2.** Офлайн эти функции не работают — это онлайн-надстройка.
15. **[Ф] Произношение — главный риск русского/белорусского TTS:** RUAccent показывает точность ударений 0,96–0,97 (COLING 2025), но по топонимам и фамилиям данных нет; в белорусском TTS ударения и омографы — известная проблема. **[В] Нужен словарь произношений, привязанный к сущностям (Wikidata QID), и прослушивание оператором эталонного города.**
16. **[Ф] Условия коммерческих API несовместимы с принципом «подготовил один раз — переиспользую»:** у Google Places можно бессрочно хранить только place_id, у Yandex Maps на бесплатном тарифе хранение запрещено. **[В] Ядро базы — открытые данные (OSM ODbL, Wikidata CC0, Wikipedia CC BY-SA, Overture CDLA/Apache); коммерческие API — только для проверки свежести «на лету».**
17. **[Ф] Wikipedia — CC BY-SA:** коммерческое использование разрешено при атрибуции и share-alike; Wikimedia просит AI-разработчиков использовать Wikimedia Enterprise (бесплатный уровень — 5000 on-demand-запросов в месяц). **[В] Порождённый рассказ, близкий к тексту статьи, рискует считаться производным произведением. Нужна политика «пересказ фактов, а не текста» и атрибуция в карточке источников; юридическую трактовку дают юристы.**
18. **[Ф] В Беларуси есть уголовная ответственность за публичное «отрицание геноцида белорусского народа» (ст. 130-2 УК, с 2022 года).** **[В] Темы Второй мировой, репрессий, религии и национальной символики требуют отдельной контент-политики и обязательной ручной проверки** — это не «редкий крайний случай», а значительная часть мемориальных объектов Беларуси (в Минске 889 мемориальных досок в OSM).
19. **[В] Главный сдвиг относительно концепта:** «рассказ = статичный текст + mp3» → «проверенная база фактов о месте (fact sheet) + несколько заранее озвученных рассказов + онлайн-слой ответов на вопросы, который берёт только факты из той же базы». Принцип «молчать, а не выдумывать» переносится и на диалог.
20. **[В] Белорусский язык в MVP — реалистичен как текст, а в озвучке — как «бета»** с явной пометкой и словарём ударений. Главный аргумент за него — содержательный: у беларуских объектов в be-Wikipedia в 2–6 раз больше статей, чем в ru и en.

- **Атрибуция в интерфейсе:** OSM («© участники OpenStreetMap»), Wikipedia (название статьи, ссылка, лицензия), Commons (автор и лицензия на каждом фото), Overture/Foursquare (NOTICE), Google (атрибуция Places и логотип).

Yandex: на бесплатном тарифе хранить нельзя. **[В]** Архитектурно это означает два слоя: «база мест», собранная из открытых данных, и «проверка свежести» через коммерческий API в момент построения маршрута, без сохранения.
- **Происхождение (provenance):** у каждого факта хранить источник, ревизию (oldid Wikipedia или версию Wikidata), дату извлечения и лицензию. Это одновременно выполняет NFR-19 и даёт ссылки для «показать источники».

## 3. Достоверность

### 3.1. Состояние дел 2025–2026

- **Пересказ данного текста.** **[Ф]** Лидерборд Vectara HHEM (обновлён 22.10.2026; 7700+ статей, задача «перескажи только по тексту»): лучший результат — 1,8% галлюцинаций; gpt-5.4-nano — 3,1%; gemini-2.5-flash-lite — 3,3%; gpt-5.4 — 7,0%; gpt-5.5 — 9,3%; claude-opus-5-5 — 9,9%; gemini-3-pro-preview — 13,6%. **[В]** Мелкие модели «послушнее» при пересказе; крупные чаще добавляют знания от себя. Для рассказа по источникам это аргумент за «малую модель + строгий промпт» на этапе извлечения фактов.
- **Фактичность в целом.** **[Ф]** FACTS Benchmark Suite (DeepMind и Kaggle, декабрь 2025): лучший общий балл — Gemini 3 Pro, 68,8%; grounding — 69,0, parametric — 76,4, search — 83,8, multimodal — 46,1. Поиск заметно повышает точность. Мультимодальная фактичность (вопрос «что на фото») — самая слабая.
- **Цитирования.** **[Ф]** Стандартные метрики — citation recall (каждое утверждение подкреплено) и citation precision (каждая цитата релевантна) из ALCE; CiteEval (ACL 2025) оценивает на уровне отдельных утверждений. Сравнение 2025 года выявило компромисс между полнотой и точностью: цитаты, поставленные при генерации, против поставленных после. Главный фактор качества атрибуции — качество поиска. Аудит deep-research-систем: самая трудная часть — фактическая поддержка, а не «ссылка работает».
- **Проверка утверждений.** **[Ф]** MiniCheck (770M параметров) — точность уровня GPT-4 на LLM-AggreFact при цене в сотни раз ниже; отдельный этап разбиения на утверждения не обязателен. **[В]** Практическая схема: генератор пишет текст с инлайн-ссылками на ID фактов из fact sheet → проверяющий (NLI-модель или LLM другого вендора) проверяет каждое предложение против процитированного фрагмента → предложения без подтверждения удаляются или переписываются → итог проверяется ещё раз.
- **Встроенные цитирования у провайдеров.** **[Ф]** Web search есть у Claude ($10 за 1000 запросов), у OpenAI ($10 за 1000 вызовов плюс токены), у Gemini — Google Search grounding ($14 за 1000 сверх 5000 в месяц). **[В]** Для «подготовки один раз» встроенный поиск удобен на этапе сбора, но итоговая привязка должна вести к **сохранённому снимку** источника, а не к живой ссылке.

### 3.2. Human-in-the-loop и показ источников

- **[Ф]** Отраслевые рекомендации (Destinations International; Bloomberg Connects): ручная проверка AI-контента перед публикацией, прослушивание аудио целиком, раскрытие факта AI-генерации.
- **[В]** Многоуровневая модель: (1) эталонный город — 100% проверка оператором; (2) остальные города — автоматическая проверка, публикация с пометкой «черновой», плюс выборочная проверка оператором (например, 30–50 рассказов на город для оценки точности); (3) жалобы пользователей перепроверяют конкретное утверждение.
- **Показ источников [В]:** в тексте рассказа — номера сносок у предложений; на экране места — карточка «Источники» (название, тип, язык, лицензия, дата); у каждого утверждения в тексте — «пожаловаться на это предложение» (уточнение к FR-41: жалоба привязывается к утверждению, а не к рассказу целиком). В аудио ссылки не произносятся.

### 3.3. Реалистичные метрики и пороги

| Метрика | Как измерять | Реалистичный ориентир [В] |
|---|---|---|
| Доля утверждений с цитатой (coverage) | Автоматически: разбиение на утверждения + наличие ссылки | ≥98% после фильтра (несвязанные утверждения удаляются) |
| Точность цитат (precision) | Ручная разметка случайной выборки ≥200 утверждений на город; доля «источник подтверждает» | ≥95% по нижней границе 95%-ного доверительного интервала (при n = 200 и наблюдаемых 97% нижняя граница ≈94%, то есть нужна выборка ≥400 или наблюдаемые ≥98%) |
| Согласие автоматического проверяющего с человеком | На той же выборке | Ориентир ≥90%, `[STAT NEEDED: собственный замер]` |
| Жалобы на неточность | Доля прослушанных рассказов с жалобой | ≤2–5%; базовый уровень `[STAT NEEDED]` |
| «Отказ при пустых данных» | Доля мест без рассказа и их корректность | Не цель минимизации; проверять, что у каждого рассказа есть ≥K фактов |

**[В] Требование «≥95% утверждений привязаны к источнику» в исходной форме выполнимо тривиально: ссылку можно приклеить к любому предложению.** Содержательная метрика — точность привязки. Её нужно мерить выборочной человеческой разметкой.

## 4. Повествование

### 4.1. Факты из практики

- **[Ф]** Длина: ≈200 слов ≈ 90 секунд; рекомендация Guide-ID — в среднем 200 слов, исключения для «захватывающих» историй; Bloomberg Connects — до ~2 минут (250–300 слов); музеи часто делают 2–5 минут, но длинные треки теряют внимание.
- **[Ф]** Одна-две мысли на остановку, «одна тема на скрипт, одна мысль на предложение»; писать для уха: активный залог, простые фразы, читать вслух и хронометрировать.
- **[Ф]** Smartify (данные 2025 года): средняя длительность прослушивания 20–40 минут достигается при 14–22 остановках; персонализированные туры дослушивают до конца в 65% случаев против 52% у готовых линейных; на родном языке слушают ≈17 минут против <11 минут на чужом.
- **[Ф]** Для AI-озвучки: не больше трёх голосов на гид; цифры, даты и аббревиатуры раскрывать словами; при ошибках писать имена фонетически; следить за омографами; раскрывать AI-происхождение и не выдавать синтез за голос реального человека.

### 4.2. Требования к рассказу (предложение для спецификации) [В]

1. **Форматы:** «Вступление» к маршруту (60–90 с: тема, что увидим, сколько идти); «у места» — основной (60–150 с, по умолчанию ~90 с); «подробнее» (+60–120 с, по запросу); «в пути» (связки 20–60 с: «через 200 метров слева будет…», контекст района); «финал» (30–60 с: итог темы, что посмотреть дальше).
2. **Структура «у места»:** крючок (5–10 с: что перед глазами, деталь, на которую посмотреть) → история (одна линия, люди и конфликт) → деталь, которую можно увидеть глазами («поднимите взгляд на фронтон…») → переход к следующей точке.
3. **Ориентация на месте:** рассказ начинается с того, где стоит слушатель и куда смотреть. Это главное отличие аудиогида от статьи; нужны данные о положении фасада и точке обзора `[STAT NEEDED: источник — OSM building + ручная разметка оператора]`.
4. **Сквозная тема маршрута:** планировщик выбирает места, а генератор связок получает тему и последовательность мест и пишет переходы. Связки порождаются на маршрут, а не на место; это отдельный тип контента, плохо переиспользуемый (см. §8).
5. **Тон и персоны:** 2–4 персоны (например, «историк», «рассказчик-краевед», «для семьи», «архитектура») = заданные тон + отбор фактов + голос. Не больше трёх голосов на маршрут.
6. **Запреты (антипаттерны AI-рассказов, [В] на основе опыта отрасли):** оценочные штампы («величественный», «жемчужина», «уникальный», «богатая история»); вода и общие места без конкретики; обращение «дорогие путешественники»; повторение одних фактов в соседних точках; фантазии о чувствах исторических лиц; одинаковая структура всех рассказов; фразы-«хеджи» («по некоторым данным») без указания, по каким. Это проверяется автоматическим линтером (стоп-лист + LLM-оценка) и дедупликацией фактов по маршруту.
7. **Повторы по маршруту:** хранить, какие факты пользователь уже слышал, и не повторять их (для заранее подготовленных вариантов — выбор варианта с минимальным пересечением).

### 4.3. Заготовленные варианты против порождения на лету [В]

| | Заготовленные варианты (концепт) | На лету под человека |
|---|---|---|
| Качество и проверка | Проверяется заранее, в том числе человеком | Проверяется только автоматически, задержка |
| Офлайн | Да | Нет (или нужна модель на устройстве — §7) |
| Цена | Амортизируется: ≈$0,01–0,15 за рассказ один раз | ≈$0,03 за рассказ за каждое прослушивание (§8) |
| Персонализация | Профиль × формат | Полная (погода, услышанное, вопросы) |

**Рекомендация:** гибрид. Ядро — заготовки (3–4 профиля × язык) из **проверенного fact sheet**. Онлайн-слой — короткие персональные вставки и ответы на вопросы, **строго из того же fact sheet**, с тем же проверяющим. Связки «в пути» порождаются при построении маршрута (онлайн, один раз на маршрут) и входят в офлайн-пакет.

### 5.2. Ударения и произношение имён собственных

- **[Ф]** RUAccent (COLING 2025): точность ударений 0,96 на омографах и 0,97 на прочих словах; Silero Stress — пакет автоударений и омографов под MIT; у stressonnx общая точность 0,938 и 0,820 на омографах. Данных именно по топонимам и фамилиям **нет**. В LLM-TTS (OmniVoice) нет способа принудительно задать ударение. В белорусском синтезе заметны дефекты ударений и омографов (проект Sonora).
- **[В] Решение в продукте:**
  1. **Словарь произношений на уровне сущности** (Wikidata QID → написание с ударением, транскрипция в IPA, «как читать» для каждого языка). Источники: поле «произношение» в Wikidata (P898, IPA) там, где оно есть, ударения в ru/be-Wikipedia, ручной ввод оператора.
  2. **Предобработка текста перед TTS:** раскрытие чисел, дат и римских цифр; расстановка ударений (RUAccent или Silero Stress для русского); для белорусского — словарь плюс ручная разметка.
  3. Передача ударений в формате движка: `+` у Yandex и Silero, SSML `<phoneme>` у Azure и Google Cloud. Для LLM-TTS — фонетическое написание или знак ударения в тексте, работоспособность нужно проверять.
  4. **Озвучка как проверяемый артефакт:** автоматическая обратная проверка ASR (распознать сгенерированное аудио, сравнить с текстом, отметить расхождения в именах) плюс прослушивание оператором для эталонного города.
  5. Английские рассказы о беларуских местах: решить политику транслитерации (BGN/PCGN или национальная система латинизации — Wikidata P5412) и произношения (ближе к оригиналу или англизированно).

### 5.3. Размер аудио для офлайн-пакета [В, расчёт]

Размер = битрейт × длительность: Opus 24 кбит/с ≈ **180 КБ/мин**; Opus 32 кбит/с ≈ 240 КБ/мин; MP3 64 кбит/с ≈ 480 КБ/мин; WAV 24 кГц 16 бит моно ≈ 2,9 МБ/мин. Типовой маршрут — 15 мест × 2 мин + 10 связок × 0,5 мин + вступление и финал ≈ 37 мин → **≈6,7 МБ в Opus 24k** или ≈18 МБ в MP3 64k. Плюс офлайн-карта (отдельная тема). Вывод: аудио не ограничивает размер офлайн-пакета; можно класть 2 языка или 2 варианта на место.

| **(в) Рассказ на лету под контекст** | Технически зрелое; проверка остаётся узким местом | ≈$0,03 за место за каждое прослушивание (≈$0,5 за прогулку из 15 мест) против разовых $0,01–0,15 | Средняя: персональные вставки ценны, полный рассказ на лету — нет | **MVP: связки «в пути» и вступление на маршрут** (один раз на маршрут). Полный рассказ на лету — не делать |
| **(г) Офлайн-ответы моделью на устройстве** | Низкая для RU/BE: языки Apple Foundation Models ограничены (русский в списке не подтверждён), доступность зависит от системного языка; Gemini Nano на Android — `[STAT NEEDED]` | 0 за запрос, но дорогая разработка | Низкая-средняя | **Не делать в MVP.** Офлайн-альтернатива: заранее порождённые FAQ к каждому месту (5–10 вопросов и ответов в пакете) — 90% ценности за копейки |
| **(д) Выбор голоса или персоны** | Высокая (десятки голосов, промпт-управление стилем) | Умножает TTS на число персон | Средняя | **MVP: 2 персоны** (например, «историк» и «лёгкий рассказчик») с одним голосом каждая. Клонирование голосов — не делать (согласия, риски) |
| **(е) Автоперевод и мультиязычность** | Высокая; Smartify: на родном языке слушают в ~1,5 раза дольше | Линейно по языкам, ≈$0,05–0,15 за место за язык | Высокая для иностранных туристов; для Беларуси — источники на be и ru, рассказ на en | **MVP: ru + en** (FR-30 поднять с У2 на У1). be — текст в MVP, озвучка — бета |
| **(ж) Иллюстрации, «было — стало»** | Фото с Commons — зрелое; генерация «исторических» изображений — **противоречит принципу достоверности** | Почти 0 (Commons) | Средняя | **MVP: 1–3 фото из Commons с атрибуцией** (около 50% объектов наследия имеют P18). «Было — стало» — после MVP, **только реальные архивные фото**. Генеративные «реконструкции» — не делать |
| **(з) Глубокое исследование города агентами** | Высокая (web search + fetch, deep research) | ≈$0,35 за место в премиум-сценарии | Высокая для городов без Wikipedia-покрытия | **MVP (у оператора):** агент собирает источники и fact sheet, оператор утверждает. Для любого города по запросу — после MVP, с пометкой «черновой» |
| **(и) Аудио-превью маршрута** | Тривиально (вступление + 3–4 «крючка» по 10 с) | ≈$0,01 | Средняя (решение «идти или нет») | **MVP** как часть вступления |
| (к) Вопросы «рядом со мной сейчас» (туалет, кафе, открыто ли) | Grounding with Google Maps решает это одной функцией | $0,014 за запрос | Высокая на маршруте | После MVP; провайдер недоступен из BY/RU, нужен региональный аналог |

## 8. Себестоимость

### 8.1. Параметрическая модель

Обозначения: `S = V × L` — число рассказов на место (V — варианты под профили, L — языки); `T` — длительность рассказа (мин); `C` — символов на рассказ (~900 символов/мин для русского, **[В]** оценка по ≈130 слов/мин); `p_in`, `p_out` — цены LLM за токен; `A` — цена TTS за минуту (или `c_char × C`).

```
Cost_place = Collect + S × (Gen + Verify) + S × TTS + Q_review
Collect   = Tin_c × p_in + Tout_c × p_out + n_search × p_search     (не зависит от V и L)
Gen       = Tin_g × p_in + Tout_g × p_out
Verify    = Tin_v × p_in' + Tout_v × p_out'                         (модель другого вендора)
TTS       = T × A          (LLM-TTS: A = 60 × 25 × p_audio_token)  или  C × c_char
Cost_city(N) = N × Cost_place + Cost_bridges(маршрут) + Q_review_city
```

Допущения [В]: V = 3, L = 2 → S = 6; T = 2 мин; C = 1800 символов; объём токенов указан в таблице. Batch-режим (−50%) используется везде, где он есть: подготовка асинхронная.

### 8.2. Цены (15.11.2026, за 1 млн токенов, batch)

Поиск: Gemini grounding — $14 за 1000; Claude web search — $10 за 1000. TTS — см. §5.1.

## 9. Свежесть данных и чувствительные темы

### 9.1. Свежесть

- **[Ф]** Google: `businessStatus` = OPERATIONAL, CLOSED_TEMPORARILY или CLOSED_PERMANENTLY (если статус неизвестен — поле отсутствует); источники обновления — владельцы, пользователи, государственные партнёры, ML по Street View. Overture: `operating_status` с мая 2026 года равен null по умолчанию; при `permanently_closed` поле `confidence` = 0; обновлён статус 8,5 млн POI — только в США. Независимых данных о годовой «утечке» POI не нашёл `[STAT NEEDED: доля POI, закрывающихся или меняющих часы за год]`.
- **[В] Практика для продукта:**
  1. Разделить данные по скорости устаревания: **история** (годы), **статус и часы работы** (недели), **события и ремонты** (дни). Хранить `fetched_at` и `valid_until` у каждого практического атрибута.
  2. Проверять статус и часы при построении маршрута и при скачивании пакета (онлайн-запрос к коммерческому API без сохранения или к собственному кэшу открытых данных); в пакет класть дату проверки и показывать её пользователю.
  3. Если часы неизвестны, нужна мягкая логика планировщика (не ставить такое место как «жёсткое окно», предупреждать). Связь с FR-10: «часы работы» — жёсткое ограничение **только при известных данных**.
  4. Кнопка «здесь закрыто или изменилось» → сигнал на перепроверку. Повторная выборочная проверка рассказов при изменении ревизии источника (Wikipedia oldid → diff → перегенерация затронутых фактов).
  5. Рассказы не должны содержать изменчивых фактов: цены билетов, часы, «сейчас здесь находится кафе». Такие сведения — в карточке места, а не в аудио.

### 9.2. Чувствительные темы: практика контент-политики [В, с опорой на отраслевые рекомендации]

- **Категории риска** (помечаются на уровне места или факта при сборе): война, Холокост и массовые убийства; политические репрессии; религия и святыни (поведение, дресс-код); национальная символика и спорные исторические трактовки (ВКЛ, межвоенный период, советский период); живые люди (только публичная роль, без частной жизни); недавние трагедии; современная политика.
- **Правила:** (1) тон уважительный, без шуток и «развлекательной» подачи для мемориалов — отдельный шаблон и голос; (2) спорные трактовки — «по данным X… по данным Y…» с цитатами, без вердикта модели; (3) запрет на оценочные суждения о живых политиках и современных событиях; (4) места категории риска — **обязательная ручная проверка до публикации**, даже вне эталонного города; (5) LLM-классификатор чувствительности на этапе сбора + стоп-лист тем.
- **Специфика Беларуси [Ф]:** с 05.01.2022 действуют закон «О геноциде белорусского народа» и ст. 130-2 УК (публичное отрицание); МВД сообщало о возбуждённых делах, в том числе о «реабилитации нацизма». **[В]** Для беларуского рынка тематика ВОВ, мемориалов и символики — зона юридического риска; формулировки должны согласовываться с юристами (агент по праву). В разных странах запуска нормы различаются, поэтому контент-политика должна поддерживать **региональные варианты формулировок**, а не одну «нейтральную» версию.
- **Раскрытие:** пометка «создано автоматически» (FR-28) — на экране места, во вступлении к маршруту (одной фразой голосом) и в описании голоса («синтезированный голос»); для OpenAI это требование политики использования.

## 10. Следствия для FR/NFR концепта

**Уточнить**
- **FR-22:** «черновой город» определять по двум измеримым порогам: (а) доля мест с ≥K подтверждёнными фактами; (б) доля мест с известными часами и статусом. Показывать пользователю уровень покрытия.
- **FR-24 и метрика ≥95%:** разделить на coverage (автоматически, ≥98%) и precision (выборочная разметка, ≥95% по нижней границе ДИ); описать протокол выборки.
- **FR-26:** вариант = (профиль × персона × язык × формат); зафиксировать конечный набор профилей (3–4) и форматов (вступление, у места, подробнее, в пути, финал).
- **FR-41:** жалоба привязывается к конкретному утверждению (предложению) с его источником.
- **FR-10:** часы работы — жёсткое ограничение при известных данных, мягкое предупреждение при неизвестных.
- **NFR-19:** провенанс — источник, ревизия, дата, лицензия у каждого факта и медиафайла; атрибуция в интерфейсе.
- **NFR-23:** заменяемость генератора и TTS дополнить **заменяемостью провайдера по юрисдикции** (разные провайдеры для разных рынков).

**Добавить**
- **FR (новое): fact sheet места** как первичный артефакт (проверенные атомарные факты со ссылками), из которого порождаются все рассказы и ответы.
- **FR (новое): словарь произношений** на уровне сущности; предобработка текста для TTS; оператор может исправить ударение.
- **FR (новое): связки «в пути», вступление и финал маршрута**, порождаемые на маршрут и входящие в офлайн-пакет.
- **FR (новое): вопросы к гиду** (текст или голос) с ответом только из fact sheet; офлайн — заранее порождённые FAQ.
- **FR (новое): фото места из Commons** с атрибуцией.
- **FR (новое): проверка свежести** статуса и часов при построении и скачивании; дата проверки в пакете.
- **NFR (новое): контент-политика по чувствительным темам** с категориями риска и обязательной ручной проверкой.
- **NFR (новое): бюджет себестоимости** — целевая стоимость подготовки места ≤$X и измерение по статьям (LLM, поиск, TTS, ручная проверка).

**Ослабить или переформулировать**
- «Каждое утверждение привязано к источнику» → **«каждое утверждение о факте»**: связки, обращения и ориентация («посмотрите налево») ссылок не требуют. Это нужно определить явно, иначе метрика неизмерима.
- «Любой город» → «любой город с пометкой уровня покрытия»; для городов без источников честно отвечать «рассказов нет, маршрут — только по карте».
- FR-30 (два языка) — поднять с У2 на У1; FR-37 (полностью офлайн) оставить для заготовленного контента, явно исключив «живые» функции.

**Убрать или не делать**
- Генеративные «реконструкции» прошлого (изображения) — противоречат принципу достоверности.
- Порождение полного рассказа на лету при каждом прослушивании — дорого и непроверяемо.

## 11. Рекомендации

### В MVP
1. Конвейер «источники (OSM + Wikidata + Wikipedia be/ru/en + Commons) → fact sheet → проверка → варианты рассказа → проверка утверждений → TTS → ASR-сверка».
2. Языки **ru + en**; **be — текст + бета-озвучка** (если выбранный провайдер TTS доступен).
3. 3 профиля интересов × 2 персоны (одна из них — по умолчанию); форматы: вступление и превью, у места (~90 с), подробнее, связки «в пути», финал.
4. Словарь произношений, автоударения для ru, обязательное прослушивание эталонного города.
5. Карточка источников с лицензиями; жалоба на предложение; пометка «создано автоматически».
6. Фото из Commons.
7. Вопросы к гиду **текстом или голосом по кнопке**, ответы из fact sheet; офлайн — FAQ к месту.
8. Агент глубокого сбора у оператора (подготовка эталонного и новых городов).
9. Контент-политика по чувствительным темам + ручная проверка мест категории риска.
10. Проверка статуса и часов при построении и скачивании маршрута.

### После MVP
- Realtime-диалог push-to-talk с ограничением на fact sheet.
- «Что это?» по камере с кандидатами из базы.
- Персональные вставки на лету (погода, время суток, уже услышанное).
- «Было — стало» с архивными фото.
- Подготовка любого города по запросу без оператора (черновой статус); дополнительные языки (pl, lt, de, zh — по рынку).
- Ответы «рядом со мной» через региональный аналог Maps grounding.

### Не делать
- Генеративные исторические изображения; клонирование голосов реальных людей; полный рассказ на лету при каждом прослушивании; on-device LLM в MVP; хранение данных коммерческих API вопреки их условиям; использование API с запретом для страны пользователя «в обход».

## 12. Развилки для этапа ADR (без выбора)

1. **Юрисдикция и провайдеры:** беларуское юрлицо + региональные или self-hosted модели ↔ юрлицо в поддерживаемой стране + мировые API ↔ гибрид (подготовка на мировых API, живые функции — региональные или открытые).
2. **LLM для сбора и порождения:** Gemini / OpenAI / Claude ↔ YandexGPT / GigaChat ↔ DeepSeek API ↔ открытые модели (Qwen, DeepSeek) на своём GPU.
3. **Проверяющий:** NLI-модель (MiniCheck-класс, self-host) ↔ LLM-судья другого вендора ↔ оба каскадом.
4. **TTS:** Gemini Flash TTS ↔ OpenAI (с учётом закрытия gpt-4o-mini-tts 06.01.2027) ↔ ElevenLabs ↔ Yandex SpeechKit ↔ Silero (коммерческая лицензия) или другая открытая модель; отдельно — решение для белорусского.
5. **Ударения:** RUAccent ↔ Silero Stress ↔ встроенная разметка движка; формат словаря произношений.
6. **Источник POI:** OSM ↔ Overture ↔ OSM + Overture; онлайн-проверка свежести через Google Places ↔ Яндекс ↔ без неё.
7. **Wikipedia:** дампы ↔ Wikimedia Enterprise (бесплатный или платный уровень) ↔ REST API.
8. **Где порождаются связки:** сервер при построении маршрута ↔ шаблоны без LLM.
9. **Живой диалог:** Gemini Live ↔ OpenAI Realtime ↔ каскад ASR → LLM → TTS (дешевле, гибче, но выше задержка).
10. **Формат аудио:** Opus ↔ AAC ↔ MP3 (совместимость с iOS и Android против размера).
11. **Объём ручной проверки:** 100% эталонного города + выборка ↔ 100% мест категории риска ↔ сплошная.
